# 意图：清爽宁静的项目管理工作台

作者：tony（产品发起人）。状态: accepted（2026-10-11 接受；同日按意图粒度规则将原 002/003 并回本链，设计稿与后端为本意图的阶段产物，见 001-spec 决策记录。2026-10-12 修订：发起人期望生产前端采用组件体系（shadcn 类）、后端用 FastAPI 最新稳定版——技术选型移交规格阶段定型，零依赖约束收缩为仅适用原型）。链: open。

## 问题

常见项目管理工具界面嘈杂、信息密度过高，个人开发者与小型团队在多项目之间切换时缺乏一个结构清晰、无干扰的工作台；现有工具的视图（看板 / 列表 / 日历 / 时间线）彼此割裂，无法围绕同一份项目数据自由切换。

## 提议的结果

一个名为 Memo 的项目管理工作台，具备：

- 首页仪表盘：汇总今日待办与整体进展
- 收件箱与「我的任务」：个人视角的任务归集
- 项目多视图：看板、列表、表格、日历、时间线、文件视图共享同一数据
- 成员、团队、动态与设置：协作所需的组织信息

整体气质「清爽宁静、结构清晰」，界面噪音最小化。

## 受影响的用户和系统

- 用户：个人开发者与小型团队
- 系统：`prototype/` 前端原型（原生 JavaScript ES 模块 + CSS，零依赖，只读转换源）；生产前端 `frontend/` 与后端 `backend/`（技术栈于规格阶段定型，发起人期望见未决问题）

## 约束

- 原型 `prototype/` 保持零依赖（原生 ES 模块 + CSS，只读转换源）——原「不引入 UI 框架与运行时依赖」约束收缩为仅适用原型（2026-10-12）
- Node.js 18+（`.nvmrc` 固定 22）
- 代码检查与格式化遵循现有 ESLint / Prettier 配置，CI 保持绿
- 前端原型先行（`prototype/`，UX 参考与设计稿转换源）；产品交付后端与持久化数据库（技术决策：FastAPI + PostgreSQL，自托管 Docker，首版不做离线）

## 未决问题

- 数据持久化方案（本地存储还是服务端 API）何时引入？——已决策：FastAPI + PostgreSQL，并入本意图链（001-spec）。
- 后端技术栈、数据库、部署形态、离线支持？——已决策（2026-10-11）：Python（FastAPI）、PostgreSQL、自托管 Docker、首版不做离线。
- 是否需要多人协作能力（实时同步、权限），还是长期保持单人工具？
- 移动端适配的优先级如何？
- 生产前端技术栈？——发起人期望组件体系（shadcn 类，倾向 Vite + React + TypeScript + Tailwind CSS + TanStack Query 数据层）、后端 FastAPI 最新稳定版；定型于规格阶段工程视角审查（高风险咨询技术负责人），2026-10-12 提出。
