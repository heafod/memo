# 意图：Memo 设计稿（从前端原型转换）

作者：tony（产品发起人）。状态：草稿。

## 问题

工程流程要求前端工作从设计稿出发：意图接受 → 设计稿迭代 → 构建生产前端，先后顺序不能乱。此前缺少设计稿环节，前端定位（原型 / 生产代码）长期模糊；已决策：现有代码为原型（`prototype/`），生产前端必须从设计稿构建。

## 提议的结果

从 001 意图产出 Memo 设计稿，作为生产前端构建的输入：

- 设计系统：以现有 `DESIGN.md` 与 `prototype/src/styles/tokens.css` 为权威基础
- 关键视图设计稿与交互流说明
- 已有成熟前端代码，采用「代码 → 设计稿」转换路径（原型即转换源）；若无前端代码的场景则直接生成设计稿
- 设计稿使用 Figma、ardot 等设计工具产出（工具中立，不绑定单一厂商）
- 设计稿经产品负责人迭代确认后，作为消费 003 API 契约的生产前端（后续意图）的构建依据

## 受影响的用户和系统

- 用户：产品负责人（设计稿评审与迭代）
- 系统：`prototype/`（转换源，只读不改）、`DESIGN.md` 与 `prototype/src/styles/tokens.css`（设计系统权威源）、后续生产前端构建

## 约束

- 设计 token 权威源不变：`prototype/src/styles/tokens.css`；机器可读设计系统 `DESIGN.md` 与之同步，`npx @google/design.md lint DESIGN.md` 保持 0 警告
- 设计工具中立：Figma、ardot 等，不绑定单一厂商
- 设计稿导出物须版本化入仓，可评审、可追溯
- 保持「清爽宁静、结构清晰」的产品气质（001 意图）

## 未决问题

- 覆盖范围：全部页面，还是核心视图优先（首页 / 项目六视图 / 任务详情 / 设置）？
- 导出物形式与存放位置（如 `docs/design/`）？
- 交互流（动效、状态转换）是否纳入首版设计稿？
