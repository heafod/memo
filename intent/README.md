# intent/ · 意图仓库

本目录是 Memo 产品的意图仓库（intent repo）：所有产品变更从一份人类可读、版本受控的 `intent.md` 原型规格出发。

## 文件约定

- `TEMPLATE.md` — 约定的 `intent.md` 模板，新意图从它复制开始。
- `NNN-<短标识>.md` — 每份意图一个文件，序号递增；头部标注作者与状态。
- `NNN-spec.md` — 与同号意图配对的需求与设计规格，由 `skills/intent-to-spec/` 技能产出：需求编号（R1、R2…）供计划与评审引用，须包含「约束满足表」「未决问题去向」「关注点及负责人」三节。

## 工作流

1. 发起人用自己的话向 Agent 描述问题（现在做不到什么、谁受影响、更好的状态、什么不在范围）。
2. 头脑风暴直到想法具体化：Agent 会追问范围、用户、约束和成功标准。
3. 请 Agent 按模板把结果写成 `intent.md`。
4. 发起人纠正 Agent 误解的内容。
5. 提交到本目录，Git 历史记录作者与时间戳，产品负责人从这里接手。

## 治理

- 证据即已提交的 `intent.md`：作者、时间戳、完整修订历史都在 Git 中。
- 产品负责人决定接受或关闭；状态字段与提交记录即决定凭证。
- 接受的意图进入需求与设计阶段，产出的 `spec.md` 应能追溯到来源意图。

## 度量

- 先行指标：从第一次对话到提交 `intent.md` 的时间（目标：小时级，而非周级）。
- 滞后指标：进入设计阶段的存活率；同一变更首次 `spec.md` 提交后对 `intent.md` 的修改次数。
