# 捕获意图（brainstorm → intent.md）

产品变更的入口技能：把发起人自己的话变成一份可评审的意图文件。意图记录「想要什么、为什么、在哪些约束之下」，不预设方案细节——那是规格阶段的事。

## 执行步骤

1. **听发起人描述**：现在做不到什么、谁受影响、更好的状态什么样、什么不在范围。接受非正式语言，不要求表述完整。
2. **像分析师一样追问**，直到想法具体：范围（做什么 / 不做什么）、用户（谁受益、谁受影响）、约束（安全 / 合规 / 技术 / 时间边界）、成功标准（做成后如何判断）。追问可调用 `.agents/skills/grill-me` 执行（其委托 grilling 技能完成访谈）。一次问一组，不要连珠炮式审讯；发起人答不上来的，记入「未决问题」而不是逼问。
3. **按模板起草** `intent/NNN-<短标识>.md`（序号取当前最大值加一，模板见 `intent/TEMPLATE.md`）：问题 / 提议的结果 / 受影响的用户和系统 / 约束 / 未决问题，头部注明作者与状态「草稿」。
4. **请发起人纠正**：逐节复述你的理解，标出不确定的推断，发起人确认或改正。发起人未回答的问题不得代答。
5. **提交**：意图文件单独提交（中文 Conventional Commits），作者与时间戳进入 Git 历史，产品负责人从此接手。

## 纪律

- **停留在问题与结果层面**：不写实现方案、不写文件路径，那是 `NNN-spec.md` 的事。
- **触发来源不限**：人的想法、工单、线上事件（维护阶段的回写）都走同一入口。
- 访谈强化（grill-me）随时可被发起人喊停，直接转入起草。
- 完整流程与治理说明见 `intent/README.md`。
